# 云寻智慧农业工作台软件

云寻是面向田块管理的农业工作台：登记地块档案并按**茬次**记录每季作物，按地块记录每次农事作业（含用量、费用、采收产量与单价），用待办排好接下来的活，并按用户填写或估计的降雨概率和土壤湿度给出水分条件提示。作物、生长期和气温只作记录，不参与提示分支；没有自动天气或传感器数据，不是综合风险评估或用药依据。打药记录会按安全间隔期给出最早采收日，统计面板按茬次算出投入产出，便于跨年对比。全部计算在本地规则引擎完成，不依赖任何外部服务。

## 快速启动

```powershell
Copy-Item .env.example .env
python -m venv .venv
.\.venv\Scripts\Activate.ps1

```

## 密码与账号恢复

正式账号可在「账号安全」验证原密码后改密，并生成由本人离线保管的一次性恢复码。登录页可用恢复码重置；服务端仅存摘要，重新生成或成功使用后旧码失效。改密/重置会撤销全部设备会话及恢复码，业务数据保留。两种凭据都丢失时，仅可由可信部署者线下核验身份后运行本机交互命令，无法核验则不能恢复。访客须先保存账号，历史账号不按用户名推断身份。详见 [密码与账号恢复](docs/ACCOUNT_RECOVERY.md)。Schema 11 仅追加可空恢复码摘要列，当前已前进到 Schema 12；两步均保留既有业务记录。

## CSV 数据导出

台账可按当前日期、地块、类型、茬次、账目范围及真实/演示来源导出全部匹配记录，包含尚未加载的页。每茬收支可导出当前范围汇总和对应台账，年度沿用作业日期口径。文件使用 UTF-8 BOM、明确单位与缺失值留空，文本公式前缀做防护；只导出本人业务字段，不含账号凭据或内部配置。CSV 仅供留档和分析，不能作为完整数据库恢复备份。无新增依赖、长期文件存储或数据库迁移。详见 [用户 CSV 导出](docs/DATA_EXPORT.md)。

## 删除保护与回收站

地块和台账删除改为移入回收站。地块删除前核对全部茬次、台账与待办数量（含已完成）；恢复保留原 ID 和关联资料，单独删除的台账仍需单独恢复。回收站保留至主动最终删除，没有自动清理。最终删除有独立确认且不可在回收站恢复，历史硬删除也无法找回。Schema 12 只追加软删除字段和索引，保留已有数据；运维数据库备份工具不变。详见 [地块与台账回收站](docs/RECYCLE_BIN.md)。

## 手机快速记账

首页和地块卡片可直接「记一笔农活」，带入地块、今天及日期适用的茬次，补录时重新匹配历史茬次。新增和编辑共用表单，费用等信息可留空后补；切换类型清除不适用字段，保存后不复用上一笔数值。未保存离开有确认，失败保留输入由本人重试，重复点击和响应丢失重试沿用现有幂等保护。草稿仅在当前页面内存中，不保存到本机持久存储，退出/换账号后清除；无离线同步或后台重试。详见 [手机记账与草稿边界](docs/MOBILE_LEDGER.md)。

## 限制与文档

已登录的新访客可在页面上方选择「保存账号」，设置正式用户名、密码和显示名称。`POST /api/auth/upgrade-guest` 只升级认证会话对应的 `is_guest=true` 账号，不接受目标用户 ID。保留原用户 ID、创建时间、所有业务对象、引导状态和演示来源，不复制数据，也不把演示记录转成真实记录；升级后仍可查看、单独清空已有演示资料。

升级与会话替换在同一个 SQLite 事务提交：用户名冲突返回 409、无效输入返回 400/422，失败保留原账号和会话。成功会撤销该访客的全部旧 Token，签发新 Token，并通过已有会话配置换发 HttpOnly Cookie 与 CSRF Cookie；后续 Cookie 写入使用新的 CSRF。旧 Token 再请求返回 401，正式账号调用升级返回 403，并发中已通过认证但重复升级的请求返回 409。升级成功后可退出，再用新凭据登录。

保存响应未确认时，页面先查询当前身份：仍为访客则可重试，已为原 ID 的正式账号则显示成功，会话失效则提示用刚设置的新凭据登录。网络无法核对时保留表单并提示稍后核对，避免误报保存失败或引导用户丢弃尚未确认的访客会话。密码仅在表单内暂存，取消或成功后移除，不写入浏览器持久存储。该能力复用 Schema 10，无新增迁移。历史未可靠标记的账号继续按普通账号保留，不按 `guest_` 前缀授予升级权限。

首次使用按真实业务数据核对「登记第一块地 → 建立第一茬 → 记第一笔农活」。登记地块会复用现有逻辑同时创建第一茬，引导不再额外建茬。每步可直接操作，跳过/继续状态保存在账号中，删除业务数据后进度会重新核对，不依赖浏览器完成标记。

新访客可主动加载演示数据，注册账号默认没有演示内容。演示为一块地、一茬番茄、3 笔台账和 2 条待办，支出 200 元、收入 600 元仅用于说明关系，不代表实际经营成果，也不计入真实引导进度。地块、茬次、台账与待办都有不可由普通写接口修改的 `is_demo` 来源标识；统计可按真实/演示/全部记录筛选，追溯及分页保持相同来源条件。

加载和清空均使用 SQLite 写事务，重复加载不会创建第二套演示数据。清空只删除有演示标记的数据；用户自行新增的台账、待办和茬次保留。被这些数据引用的演示地块或茬次会保留并转为普通资料，页面报告保留数量；再次加载使用新 ID，不会把保留资料重新归为演示。修改已有演示记录仍保持演示标记，新增在演示地块下的自己的记录则会保留，表单对此有提示。

Schema 10 向前增加来源标识、账号引导状态、显式访客身份和演示加载状态表，既有数据默认真实，保留所有记录。升级前的账号无法可靠区分访客与同名注册账号，因此均按普通账号保留，不按用户名猜测访客身份；重新使用「访客登录」可获得演示入口。接口为 `GET/PATCH /api/onboarding`、`POST/DELETE /api/demo-data`，仅本人可读写，加载仅允许显式标记的访客。

登录后的默认入口是首页，展示本人登记的今日/逾期待办、相关地块、农活计数及登记间隔期提醒。没有地块或待办时提供登记、安排待办和查看建议入口，不生成虚构农情；采收提醒直接使用地块接口已计算的登记结果。

完成待办后可选择「顺便记入台账」，也可以稍后从最近完成清单进入。完成只更新待办；打开或取消草稿不创建台账，保存失败不撤销完成。草稿带入地块、实际完成日（本机日期）、唯一适用的茬次和标题/备注，作业类型默认「其他」，用量、费用、产量等须本人核对填写。杂事需要先选择地块。首页直接记账与待办记账复用台账表单，保存后刷新地块计数和提醒，进入统计时重新查询。

台账 POST 新增可选 UUID4 字段 `submission_id`，不影响旧调用。相同用户和提交标识、相同规范化业务字段返回同一记录；内容不同返回 409，要求查看或编辑已保存记录。前端在重试中保留标识，待办记账使用稳定的待办 UUID，因此取消、重新打开或刷新后重试也不会重复记入同一待办。后续纠正请编辑已有台账；额外的独立作业可从「记一笔农活」新增。实现复用记录主键，不增加数据库表或迁移。

台账支持新增与编辑，按作业日期匹配茬次，只有起始日已知且唯一命中时才自动归属。日期重叠或起始日不明时，须选择具体茬次或明确选择「未归茬」；日期未命中任何茬次（如季间空档）保留为未归茬。显式选茬时，日期必须在该茬次已知的起止日期内（含首尾两天），不符则提示并拒绝保存。已有记录不会自动重新归茬。

API `POST /api/farm-records` 与新增的 `PATCH /api/farm-records/{id}` 复用完整表单校验；PATCH 整体替换业务字段（需提供地块、类型、日期），保留记录 ID、用户与创建时间。`season_id` 省略时按日期匹配，传具体 ID 时校验属于本人所选地块，显式传 `null` 时保留未归茬。不适用字段会清空：仅打药保留间隔期，仅采收保留产量与单价，施肥与打药可填写投入品名称。

台账可按地块、作业类型及作业日期范围筛选。`GET /api/farm-records` 新增可选参数 `kind`、`date_from`、`date_to`（日期含首尾），与已有 `plot_id`、`limit`、`cursor` 组合使用。翻页须携带相同筛选条件，切换条件或修改记录后从第一页重查。

统计面板按地块、历史茬次和作业年份查看「已记录收支差额」，公式为已记录收入减去已记录支出；未记录的人工、地租等成本不会自动包含。费用为 0 是已填写，费用为 null 才计入「费用未填」。采收收入仅汇总产量、单价均填写的记录，不完整记录单独提示「采收待补录」；已记录产量仍累加已填的采收数量，即使其单价待补。若某项全部未填，页面显示待补录而非用零金额掩盖缺失。

年度口径为台账 `happened_on` 作业日期：跨年茬次只汇总所选年内的记录，全部年份为整茬累计，互不重复；茬次起止日仅用于标识茬次，不用来划分收入年度。亩均指标按地块当前登记面积计算。点击支出、收入、差额或待补录数量可进入相同统计范围的台账并直接编辑，返回时保留地块、茬次与年份筛选；手机端使用茬次卡片。

`GET /api/farm-records/economics` 支持可选 `plot_id`、`season_id`（`unassigned` 表示未归茬）、`year`。原有 `net_revenue`、`net_per_mu` 等金额字段保留，新增完整度计数及 `available_years`、`year_basis`。台账追溯使用相同的地块/茬次/日期条件及 `economics_scope=all|cost|revenue|missing_cost|incomplete_harvest`，与原有游标分页兼容。缺失费用和不完整采收计数可能包含同一笔记录，不能直接相加作为唯一待补录记录数。

采收提醒按同一地块全部茬次和作物的已登记施药记录，取「施药日 + 用户填写间隔天数」最晚的一天；查询日之后的施药记录不参与。换茬不会解除未结束的提醒。间隔期须按具体产品标签手工填写，软件仅核对输入的日期算术，不确认实际用药或采收合规性。

当前是 SQLite 单机版本，不包含 PostgreSQL、Redis、Docker、公网 SaaS、计费或多租户。详见 `docs/V1_SCOPE.md`、`docs/ARCHITECTURE.md`、`docs/SECURITY.md`、`docs/TESTING.md`、`docs/DEPLOYMENT.md` 和 `docs/RELEASE.md`。
