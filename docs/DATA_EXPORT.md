# 用户 CSV 导出

## 页面入口

- 农事台账：「导出当前筛选台账 CSV」，导出点击时的日期范围、地块、作业类型、茬次、账目范围和真实/演示来源条件。
- 统计面板「每茬收支」：「导出收支汇总 CSV」和「导出对应台账 CSV」。先选择地块及历史茬次，可取得单茬汇总及全部对应记录。年度按**作业日期**划分，跨年茬次只计所选年度内的记录，选择全部年份为整茬累计。
- 从支出、收入或待补录数字进入明细后，仍可按该追溯范围导出台账。

导出不受当前页和「加载更多」影响，服务器重新读取全部匹配数据。文件名包含业务类型、数据来源、地块/茬次及日期或年度范围和导出日期。页面显示处理中、结果数量或失败原因，可重试；导出不会清空筛选或改动业务数据。空结果仍提供只有表头的 CSV，并明确提示。

CSV 用于留档和分析，**不是完整数据库恢复备份**：不包含账号、密码摘要、恢复码摘要、会话、完整地块/茬次档案或待办等所有业务对象，亦不提供用 CSV 恢复数据库的入口。完整恢复仍使用部署文档中的 SQLite 备份流程。

## 字段与口径

台账列包括地块、作业作物、茬次作物、归茬情况、茬次起止日期、作业日期、类型、投入品、原填写用量及单位、费用（元）、采收产量（公斤）、采收单价（元/公斤）、已记录收入（元）、登记间隔期（天）、说明与真实/演示来源。适用类型以外的字段留空，费用、产量、单价未填也留空；明确填写的 0 保持数值 0。结束日期空白与页面的进行中状态对应；缺失开始日期同样保留空白，不编造日期。

汇总复用页面统计结果及缺失计数：**已记录收支差额 = 已记录收入 − 已记录支出**。只有产量和单价均填写的采收参与收入；费用未填、采收待补录数量单独列出。同一记录可同时属于两类待补录，不能将两类数量直接相加视为唯一记录数。某金额全部待补录时导出空白，明确的零值仍是数值；差额仍表示当前已记录部分，不替未记录的人工、地租等估算成本。亩均指标采用地块当前登记面积，与页面一致。

明细收入保留乘法计算精度，汇总沿用页面的最终两位小数口径，避免逐笔取整后相加产生额外误差。用量是原填写的自由文本，不能将不同单位自动相加。演示数据在明细中逐条标识；汇总保留当前真实/演示/全部来源范围。CSV 下载对应查询执行时的数据，分别下载汇总和明细之间若有修改，应重新导出以核对同一版本。

## 中文 Excel 与公式防护

文件使用带 BOM 的 UTF-8、逗号分隔和 CRLF 行尾；标准库 csv.writer 为所有字段加双引号并转义引号，正确保留字段内逗号和换行。微软说明 [UTF-8 CSV 带 BOM 可正常打开](https://support.microsoft.com/en-us/excel/opening-csv-utf-8-files-correctly-in-excel)。Excel 仍可能自动识别日期或前导零；有精确文本格式要求时，可通过数据导入指定列类型。

对所有文本业务列检查 ASCII/全角 `= + - @` 及前导空白、控制字符绕过，在危险内容前增加**引号内的 Tab 和单引号**，使其作为文本处理；CSV 引号转义也阻止用分隔符或引号开启新公式单元格。真正的数值列按数值序列化，负收支差额不会被加文本前缀，仍可计算。防护只改变导出副本，不修改数据库。

此策略参考 [OWASP CSV Injection](https://raw.githubusercontent.com/OWASP/www-community/master/pages/attacks/CSV_Injection.md)。不同表格软件及编辑后再次保存可能有不同的解释规则，不能宣称一种 CSV 转义能保证所有软件及后续改写都安全。程序化分析应知道危险文本包含保护前缀，不应擅自去除后再作为公式打开。

## 接口与权限

- `GET /api/farm-records/export.csv`：接受现有台账筛选参数 `plot_id`、`season_id`（含 `unassigned`）、`kind`、`date_from`、`date_to`、`year`、`economics_scope`、`data_scope`；不使用 `limit` 或 `cursor`，不会导出当前页的子集。
- `GET /api/farm-records/economics/export.csv`：接受 `plot_id`、`season_id`、`year`、`data_scope`，与现有统计接口相同。

两者均要求现有 Cookie 或 Bearer 认证，只取当前服务端用户 ID，不接受目标用户 ID。显式地块和茬次会校验归属及关联关系，其他用户/不存在的实体返回 404。CSV 数据列使用显式白名单，不输出业务内部 ID、密码/恢复码/Token 摘要、配置或其他用户资料。关联查询再次限定地块与茬次归属，避免异常历史关联泄露他人名称。

返回 `text/csv; charset=utf-8`、`Cache-Control: no-store`、安全编码的 `Content-Disposition` 文件名，以及 `X-Export-Row-Count` 结果行数。CORS 只额外开放上述下载响应头，沿用已配置来源与认证策略。无新增依赖、文件存储、数据表或迁移，CSV 本身不增加迁移；当前随回收站升级为 Schema 12，导出同样排除回收站资料。

当前单机范围采用单次读取、内存生成完整文件，先完成查询与编码再返回，失败时不会交付半个 CSV。没有针对超大规模数据做容量/并发压力验收；大规模导出若成为真实需求，可再评估流式查询和下载。
