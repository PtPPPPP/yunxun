# 地块与台账回收站

## 删除和恢复规则

地块和农事台账的普通「删除」现在会移入回收站，不再直接清除数据。地块确认框先从服务器核对受影响的茬次、全部台账、其中已单独删除的台账、全部待办数量，包含已完成待办。确认期间新增/删除关联资料，或更换删除状态时，服务器拒绝旧的确认范围（409），要求重新核对。

点击侧栏「回收站」可查看本人删除的地块及单独删除的台账。资料**保留至用户主动最终删除，当前没有自动清理或固定到期日**。回收站不是经营统计的一部分。

- 删除地块只标记地块，保留原地块 ID、全部茬次、全部台账、待办及完成状态，子项跟随地块从正常查询隐藏。恢复地块解除标记，关联数据一并重新可见，不会新建一个空地块。
- 单独删除台账会标记该台账。随后删除和恢复地块，也不会把这笔此前单独删除的台账自动恢复。地块恢复后，再单独恢复它。
- 所属地块仍在回收站时，不能单独恢复台账；页面说明先恢复地块。正常页面也不能向隐藏地块新增或移动记录、修改其茬次或待办。
- 已删除数据从地块卡片、茬次选项、台账分页、计数、待办和首页、登记采收间隔提醒、收支统计、年度选项、CSV 导出及首次使用进度中排除。独立的杂事待办不受地块删除影响，历史农活建议仍属于独立的建议历史，不因地块删除而丢失。

恢复保留原有业务字段，不重新归茬、不重算或覆盖用户填写值。已记录收支根据重新可见的台账重新汇总。页面会刷新地块、茬次、待办及统计相关状态，清理受删除影响的选择。

## 冲突与重复操作

「一块地只有一个进行中茬次」的数据库唯一索引继续保留，隐藏地块的原茬次也仍受该约束保护。隐藏地块不可另开茬，正常删除/恢复不释放或替换茬次，因此不会为了恢复而结束另一茬。检测到异常的多活跃茬次或跨地块/跨用户关联时，恢复返回明确的 409，事务不修改任何资料，需联系部署者核对。

单独删除台账期间，如果用户修改了所属茬次日期，使作业日期不再落入当前起止日期，恢复返回 409，先核对茬次日期。有关联回收站台账的茬次不能直接硬删，避免恢复后无声丢失归茬关系；先恢复或最终清理相关台账再处理茬次。

普通删除首次成功返回 200；重复删除返回 404，原删除时间不改变。恢复首次返回 `changed=true`，已恢复再请求返回 200、`changed=false`，不重复创建资料。最终删除后重复清理/恢复返回 404，不能凭空重建。所有变更使用 `BEGIN IMMEDIATE`，并在写锁下重新检查归属、状态、确认版本与关联。

恢复与最终删除竞争时，先完成的事务决定结果：若先恢复，最终删除因对象已不在回收站返回 409；若先最终删除，恢复返回 404。不会出现只删除部分子项的中间结果。确认版本也区分台账的不同删除周期，旧对话框不能清掉后来再次删除的资料。

## 最终清理与恢复边界

「最终删除」有独立确认框，明确显示不可恢复和关联数量。最终删除地块会一起物理删除其所有茬次、台账和待办，包括此前单独移入回收站的台账。最终删除单笔台账只删除该笔，不影响地块及其他记录。请求必须明确确认，并携带当前回收站条目的版本；范围已变化则重新核对。

**历史版本已硬删除、已最终删除、或数据库文件已经丢失的资料，不能通过回收站恢复。** 回收站依赖同一个 SQLite 数据库，不能代替运维备份。原 `scripts/database_admin.py` 的备份、完整数据库恢复和验证职责不变，不通过回收站覆盖数据库或替人批量回滚。恢复数据库旧备份仍会恢复当时整库状态，包括当时的删除标记及会话凭据，按原运维流程处理。

演示清理仍仅处理有演示标识的数据。演示资料在回收站中时，清空演示会返回提示，要求先恢复或明确最终删除，避免绕过回收站无声清除。用户自行新增的真实数据继续按原规则保留。

## 实现和接口

Schema 12 向 `plots`、`farm_records` 增加可空 `deleted_at` 和用户/删除状态索引，既有数据默认可见；不增加独立历史表，不复制业务记录，不改写历史硬删结果。迁移保留数据及原有单活跃茬次唯一索引，升级前仍应备份。

- 既有 `DELETE /api/plots/{id}` 和 `/api/farm-records/{id}` 保持路径，改为软删除。地块响应保留原 `deleted_records`、`deleted_tasks` 字段，表示本次影响的关联数量。
- `GET /api/plots/{id}/delete-impact` 返回计数及确认版本，地块删除新增可选 `expected_revision`；旧客户端仍可删除，但删除语义也是可恢复的。
- `GET /api/trash` 返回本人的删除资料及保留说明。地块隐藏的普通子项不重复列成单独台账；仅单独删除的台账另列，并说明父地块是否仍隐藏。
- `POST /api/trash/plots/{id}/restore`、`/api/trash/records/{id}/restore` 恢复原资料。
- `DELETE /api/trash/plots/{id}`、`/api/trash/records/{id}` 仅允许清理回收站对象，须 `confirm=true` 与 `expected_revision`。

所有接口复用认证、Cookie/CSRF 和统一错误处理，只从服务端身份取用户 ID。其他用户或不存在的 ID 统一返回 404；回收站使用业务字段白名单，不返回账号、凭据或内部部署信息。

当前没有自动到期、批量清空、跨库恢复或复杂版本历史。回收站按本人资料一次读取，符合当前单机规模；尚未针对超大回收站进行容量压力验收。
