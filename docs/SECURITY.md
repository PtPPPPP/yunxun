# 安全边界

- 访客升级仅依据数据库 `users.is_guest`，认证依赖从服务端查询用户，用户名的 `guest_` 前缀不授予权限。Schema 10 以前无法可靠识别的历史账号保持普通账号，不批量转换。升级请求禁止额外字段，用户 ID 始终取自当前认证身份。
- 账号升级在 `BEGIN IMMEDIATE` 事务内再次核对访客身份，更新凭据和显示名称、清除访客标记、撤销该用户全部旧 Token 并插入新 Token；任何数据库错误都整体回滚。保留原用户 ID，业务对象和其他用户会话不变。用户名唯一索引冲突转为稳定的 409。
- 升级沿用认证限流、Cookie/CSRF 校验、密码哈希和 Token 摘要。成功响应 `Cache-Control: no-store`，复用 Cookie 的 Secure、SameSite、HttpOnly 及有效期配置，同时更换 CSRF Cookie。客户端每次写入读取当前 CSRF，不缓存旧值。旧访客会话不再可用，正式身份不能再次升级或借此修改其他账号。
- 并发已认证快照中的第二次升级返回 `GUEST_ALREADY_UPGRADED`（409），新正式会话再次调用返回 403，使用被撤销的 Token 返回 401。前端用同步请求锁防止重复提交，并在传输结果不明时查询身份；网络未恢复时保留凭据和核对入口，不自动退出访客。

- 密码使用哈希保存，Token 只保存摘要；Bearer 兼容路径继续保留。
- Cookie/CSRF、CORS、请求限流、输入长度限制和请求 ID 日志继续生效。
- 系统不接入任何外部模型服务，也不保存外部服务的 API Key 或凭据；审计记录不输出密钥内容。
- 今日农活建议完全由本机规则生成，不依赖网络调用，因此不存在把第三方返回结果当作诊断依据的风险。
- SQLite、单进程限流和本地部署限制了多实例公网使用；公网、SaaS、计费和多租户不在当前范围。
- 数据库 Schema 6 迁移会删除会话、消息和幂等表；执行前必须按发布流程备份，禁止通过删除数据库掩盖迁移失败。

## 密码管理与恢复

`POST /api/auth/change-password` 与 `/recovery-code` 仅接受当前认证正式用户，禁止额外目标字段，写入前在事务内复核当前密码与身份快照。Cookie 写入继续要求 CSRF。`POST /api/auth/recover-password` 必须验证用户名对应的一次性高熵恢复码，不依赖现有登录身份或公开资料。不同失败原因返回统一提示，叠加 IP、账号和认证限流，429 保留 Retry-After。恢复码只有生成响应包含原文，服务端仅存域隔离摘要，响应 no-store，无查询接口。改密、重置、恢复码消费与全部会话删除原子提交；登录发 Token 时复核最新密码摘要，失败不发 Token。

恢复凭据由用户离线持有，丢失后只允许可信部署者独立核验身份并在本机交互命令中重置；无凭据、无可信核验则不能恢复。本机文件权限是管理边界，无法约束已能直接写数据库的操作系统用户。历史账号不批量转换，访客须先保存正式账号。所有路径保持用户 ID 和业务数据。完整规则及单进程限流边界见 [密码与账号恢复](ACCOUNT_RECOVERY.md)。

CSV 导出仅依据认证身份查询并校验显式地块/茬次归属，关联查询再次约束用户和地块；汇总关联也限制地块所有者，异常历史关联不泄露他人名称。业务列白名单不包含用户信息、凭据摘要、Token、内部 ID 或配置。文本字段转义分隔符/引号/换行并防护公式前缀，数值列保留计算能力；文件名清理控制字符和路径符号后编码，响应 no-store。浏览器不将非 CSV 响应误下载为文件，导出文件不在服务端持久存储。CSV 防护与其他表格软件、编辑重存的边界见 [用户 CSV 导出](DATA_EXPORT.md)。

回收站所有查询与变更由认证用户 ID 限定，恢复和最终删除在写锁下复核归属、状态及关联范围。最终删除要求明确确认及当前版本，不能清理正常可见对象；跨用户/异常关联拒绝并回滚，不依赖客户端过滤。软删除资料从正常业务读取、统计和导出中排除。原数据库备份工具职责不变；回收站不保证恢复历史硬删除或数据库丢失。规则见 RECYCLE_BIN.md。

## 手机草稿与账号切换

业务表单仅存在页面内存，退出/换账号后卸载，不写 localStorage、sessionStorage 或 IndexedDB。地块、茬次、待办结果和本机建议响应带账号范围，useAccountGuard 丢弃旧身份的异步读写回调，防止迟到响应污染新用户表单。beforeunload 由浏览器决定是否提示，不能承诺强制关闭进程后的恢复。无后台离线同步和自动重试。
