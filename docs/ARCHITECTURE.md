# 当前架构

当前工作区使用 FastAPI + React/Vite + SQLite，Schema 12，应用默认版本仍为 1.0.0。浏览器向本机或局域网内配置的后端发送请求；业务建议由本机规则计算，不调用外部模型，也不自动获取天气。依赖声明中的 SQLAlchemy、Alembic、psycopg 和 redis 尚无当前业务接入，不构成已实现架构。

## 数据模型与归属

| 对象 | 职责与关联 |
| --- | --- |
| users / auth_tokens | 身份、显示名、服务端访客标记、引导跳过、可空恢复码摘要；不透明会话 Token 仅保存摘要 |
| plots | 用户所属地块，面积、土壤、灌溉、备注、演示来源和删除标记，不保存作物字段 |
| plot_seasons | 用户/地块所属茬次，作物、起止日期与演示来源；部分唯一索引保证每块地只有一茬 ended_on IS NULL |
| farm_records | 用户/地块/可空茬次关联，作业日期、类型、适用业务字段、来源和删除标记 |
| farm_tasks | 用户、可空地块、到期日和完成时间；无地块为杂事，不是自动执行的农事事实 |
| tool_records | 本机规则建议输入/结果的独立历史，不属于地块级联回收站 |
| demo_data_state | 用户演示加载状态，写事务内保证重复加载不重复产生资料 |

业务入口在 api/routes，校验在 schemas 与 services/farm，数据访问复用 repositories，账号、演示/引导、回收站分别由 repositories_account、repositories_onboarding、repositories_trash 封装。关联实体必须同属当前用户且符合所选地块，不能只依赖前端选项或单列外键。新建、更新、删除/恢复在 SQLite 写锁下复核关联，避免检查与落库之间被并发删除。新增枚举集合不使用数据库 CHECK；tool_records 中旧 CHECK 是保留的历史结构。

## 日期、台账与幂等

日期按真实日历解析后仍以 ISO 日期字符串交互，结束日不早于开始日。台账新增和编辑共用请求字段、业务准备函数及表单；编辑整体替换业务字段，保留 ID、用户、创建时间和演示来源。不适用类型字段清空，仅采收参与产量/收入计算，仅打药保留间隔期。

归茬省略时按作业日期匹配：必须只有一个适用茬次且开始日明确；有歧义返回 422。显式 null 表示未归茬，指定 ID 则检查用户、地块和已知日期范围。未命中任何茬次可保持未归茬。不能直接把历史记录归入当前活跃茬次。普通编辑保留已有选择，日期不符必须纠正或明确改选。

台账游标按 (happened_on, id) 倒序，建议历史等按 (created_at, id)。日期、地块、茬次、类型、来源和账目范围在 SQL 中先过滤，再分页。客户端切换筛选或编辑后重查第一页，并隔离旧筛选和加载更多的迟到响应。

新增可携带可选 UUID4 submission_id，服务端以用户和提交标识派生记录主键，主键冲突时核对规范化业务字段；原样重试返回同一行，内容不同返回 409，不覆盖也不复活回收站记录。旧客户端不传标识时保持分别新增。待办记账使用稳定待办 UUID，其他表单成功后换新标识。没有恢复已删除通用幂等表，也不建立离线队列。

## 首页、手机表单与引导

App 管理功能入口、待办完成提示、内存草稿和统计筛选。HomeWorkspace 展示本人今日/逾期待办、真实地块计数及复用的登记提醒；LedgerWorkspace 同时服务普通台账、首页/地块快速入口、待办记账和统计追溯。完成待办与保存台账是两个独立确认动作，打开/取消/失败不撤销完成，也不自动创建台账。

UnsavedChangesProvider 注册表单修改和保存状态，保护功能切换、取消、退出及统计返回，刷新/关闭交给浏览器 beforeunload。草稿不写浏览器持久存储，退出或切换账号后卸载；useAccountGuard 及带账号的数据容器拒绝旧账号异步结果覆盖新账号地块、茬次、待办。弹层约束键盘焦点，关闭后恢复焦点并解除背景滚动锁。手机按类型快捷选择和单列输入，桌面保留双列和下拉框；收支桌面表格、手机卡片使用同一数据源。

首次引导从真实非演示地块、茬次和台账判断三步完成，只将跳过状态保存在服务端。创建地块已经创建第一茬，引导不额外建茬。访客自愿加载演示，注册用户默认没有演示；演示标识不可由普通写请求修改。清理演示只处理标识数据，保留用户新增内容及必要祖先并转为真实资料；演示在回收站时要求先恢复或明确最终清理。

## 收支、追溯、提醒与导出

统计与追溯复用 _farm_record_conditions。年度依 happened_on 的 1 月 1 日至 12 月 31 日划分，跨年茬次在不同年度不会重复计算同一笔。费用 NULL 才是未填，0 是有效费用；已填产量单独累加，收入仅来自产量和单价都完整的采收。缺失费用/不完整采收数量可能重叠，不能直接相加为唯一记录数。空茬次不制造缺失记录。原 net_revenue、net_per_mu 字段保持兼容，页面称已记录收支差额，亩均以当前登记面积计算，不默认包含未记人工与地租。

EconomicsPanel 维护查询与追溯入口，App 保留地块/茬次/年度/来源筛选。金额或待补录数量打开同范围台账；编辑后重新核算。请求序号隔离过期响应，失败不展示假零值。

登记采收提醒在同一地块所有茬次/作物的已登记施药记录中，排除查询日之后的记录，取施药日 + 输入间隔天数的最晚日期。换茬不解除此前未结束的约束。无按农药名称自动预填固定间隔期；只验证输入算术，不确认产品标签或合规。

CSV 端点在线程池查询全部匹配记录并以内存响应输出，复用相同归属和筛选；白名单字段不含凭据，csv.writer 处理特殊字符，UTF-8 BOM 适配中文，文本公式前缀防护保留正常数值，NULL 保留空。前端处理下载中/成功/失败并释放 Object URL；不新增长期文件存储。CSV 不等于数据库恢复备份。

## 认证与恢复

浏览器使用 HttpOnly 会话 Cookie 与 CSRF Cookie，写请求发送 X-CSRF-Token；接口仍兼容 Bearer。两者同时提供时校验身份一致，不要求浏览器同时保存并发送 Bearer。Token 是服务端数据库会话，不因配置名含 JWT 就成为 JWT。CSRF 失败在中间件直接返回统一 403 JSON，保留请求 ID、安全头和日志。

访客升级按服务端 is_guest，在单个事务内保留用户 ID 更新账号并替换全部旧会话，不能按用户名 guest_ 推断权限。用户名唯一冲突为 409，失败整体回滚。成功重发会话和 CSRF；客户端结果不明先核对身份。

改密验证当前正式用户原密码；一次性恢复码高熵、仅在生成响应出现、服务端仅存摘要，换码/消费后旧码失效。改密/重置与全部会话和恢复码撤销共同提交，防止竞争补发旧会话。无公开信息重置入口。凭据都丢失需可信部署者线下核验后用本机交互命令，不能核验则不能恢复。恢复失败统一提示，配合账号/IP 限流；当前限流单进程、重启重置。

## 迁移与恢复边界

PRAGMA user_version 逐步前进，每一步事务提交，失败只回滚该步；已经提交的前面步骤不自动降级。启动拒绝高于支持版本的数据库。

| Schema | 作用与保留规则 |
| --- | --- |
| 6（历史） | 移除 AI 会话、消息、通用幂等表与模型偏好；该历史变更会删除相应旧资料，不宣称保留所有旧 AI 内容 |
| 7–8 | 增加地块、台账、待办和采收字段 |
| 9 | 把地块作物/日期搬到茬次并归属既有记录，删除 plots 的作物和日期列 |
| 10 | 添加 is_demo、is_guest、onboarding_skipped 和演示状态；既有业务默认真实，历史用户默认非访客 |
| 11 | 追加可空 recovery_code_hash，不生成或暴露历史恢复码 |
| 12 | plots 和 farm_records 追加可空 deleted_at 和索引，既有资料默认可见，原单活跃索引保留 |

回收站只标记地块和单条台账；地块子项继承父级可见性，保留所有原 ID/关联/完成状态。先单独删除的台账不会随父恢复自动复活。普通列表、计数、统计、导出、引导与建议地块选项一致排除隐藏资料。恢复检查异常关联和茬次冲突返回 409，不静默覆盖；最终清理确认版本并在一个事务内先删子项，失败整体回滚。保留至主动最终删除，无自动到期，历史硬删除不能恢复。

运维数据库备份恢复职责仍由 core/backup 与 scripts/database_admin 承担。回收站、CSV 和整库备份是不同能力；不把本机测试当成生产备份计划或灾难恢复验收。
