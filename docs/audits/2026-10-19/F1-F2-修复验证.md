# F1、F2 修复与验证

日期：2026-10-19。仅修复退出确认和会话响应隔离；F3～F6 未纳入本轮。开始时 Git 只有未跟踪的 `docs/audits/`，原审计报告、探针和结果文件未改写。

## 已实现

- 退出前保存不含凭据的退出待确认标记并隐藏资料。请求失败不再伪装成已退出，显示明确状态和重试；刷新、重新打开页面及网络恢复时继续确认，不静默恢复原账号。
- 区分请求未送达与服务端已撤销但响应丢失：退出成功或身份核对返回 401 才清除标记，无法核对则保留。退出未确认时阻止重新认证；会话变化返回 409，并说明已停止旧退出请求以保护新会话；CSRF 失败提示刷新后重试。
- 认证响应新增不可用于认证的 `session_id`，由独立域 HMAC 生成，不等于 Token 或数据库认证摘要。浏览器退出绑定原会话，旧重试不能撤销同账号重新登录或另一账号的新会话。
- 退出响应不发送 Set-Cookie，只幂等撤销对应服务端 Token。这样旧请求晚到或旧响应晚到都不能删除后来登录的 Cookie。已撤销的 HttpOnly Cookie 不再能认证，留到下次登录覆盖或自然过期；HttpOnly、Secure、SameSite 和 CSRF 保护保留。旧 Bearer 无请求体调用继续兼容。
- SessionBoundary 提供统一轮次，退出、重新认证及会话替换使旧轮次失效。bootstrap、登录/注册/访客、姓名保存、访客升级及核对、账号安全和恢复的身份回调均检查轮次；useAccountGuard 也接入同一机制，包含迟到成功、迟到错误和 A→退出→A。
- 没有新增运行依赖、数据库字段或迁移；Token、密码和业务草稿不写入 localStorage、sessionStorage 或 IndexedDB。localStorage 只增加退出待确认标记。

主要实现：[App.tsx](../../../frontend/src/App.tsx)、[SessionBoundary](../../../frontend/src/hooks/useSessionBoundary.tsx)、[退出标记](../../../frontend/src/lib/logoutIntent.ts)、[认证路由](../../../backend/app/api/routes/auth.py)、[会话引用](../../../backend/app/core/security.py)。安全边界和测试说明同步到 `docs/SECURITY.md`、`docs/TESTING.md`。

本轮保留了会话冲突时的保护策略：另一处登录替换 Cookie 后，旧退出返回 409，页面继续显示退出未确认，不自动撤销或接管新账号。浏览器清除本站数据会清除退出意图标记；服务端撤销一旦确认则不依赖该标记继续有效。
