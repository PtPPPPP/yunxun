# F3 与今日农活表述修复

日期：2026-10-19。本轮在已有 F1/F2 未提交改动之上修复 F3，保留原审计报告、探针及历史资料；F4～F6 未纳入本轮。

## 已实现

- 建议结果保存生成时的地块 ID、名称、全部输入、请求版本与文本快照。待办标题使用实际提交的作物，关联地块和备注读取同一快照，不再混用当前地块和旧文本。
- 修改地块、取消地块选择，或修改作物、生长期、降雨概率、土壤湿度、气温，立即清除旧结果与保存入口。输入改回原值也不会复活旧结果。
- 请求版本结合 F1/F2 的会话轮次隔离迟到成功、迟到错误和加载状态。修改输入后可以直接发起新生成，旧响应不能覆盖新结果；最新生成失败时不退回旧建议。
- 同一版本的重复生成、同一结果保存中的重复点击均由同步锁阻止；确认保存后该结果不能再次保存。保存期间锁定条件和生成入口，失败保留同一结果供重试，输入变更后新结果有独立保存状态。
- 页面、登录介绍、帮助、README 与后端新生成文本收窄为“水分条件提示”。说明条件由用户填写或估计、初始值仅为示例，没有自动天气或传感器数据。移除“当前风险”及高/中/低综合风险表述，明确作物、生长期和气温只作记录，不参与分支判断。
- 原湿/干阈值保持不变：降雨概率 ≥60 或湿度 ≥65 走偏湿分支；否则仅降雨概率 ≤30 且湿度 ≤35 走偏干分支；其余不触发这两项条件。未新增或验证农艺规则。
- 保留 `/api/decision` 的原五项请求字段及 `reply` 响应结构，待办 API、数据库与历史记录结构不变。无新增依赖、迁移、模型或外部服务。

主要实现：[App.tsx](../../../frontend/src/App.tsx)、[DecisionWorkspace.tsx](../../../frontend/src/components/DecisionWorkspace.tsx)、[后端提示文本](../../../backend/app/services/decision.py)。回归位于 [decision-consistency.spec.ts](../../../frontend/e2e/decision-consistency.spec.ts) 与 [test_decision_service.py](../../../backend/tests/test_decision_service.py)。

## 边界

已送达的旧生成请求仍可能按原 API 写入建议历史，保存的是原提交条件；前端仅使其失效，不回滚历史。既有历史建议文本不批量改写。保存锁覆盖本页面同一结果的重复点击；原待办 API 没有新增跨刷新幂等协议，不能将其描述为响应完全丢失后的跨刷新去重保证。
