# F4、F5 修复与验证

日期：2026-10-19。本轮在已有 F1～F3 未提交改动之上修复 F4、F5，保留原审计报告和复现资料。未处理 F6，未改前端、API 字段、数据库 Schema 或依赖。

## 实现

- `create_plot_with_first_season` 使用一个连接和一个 `BEGIN IMMEDIATE` 事务，调用复用的地块、茬次 INSERT 操作；任一步异常由现有连接管理器整体回滚，仅在成功退出事务时提交。
- 普通茬次编辑和 `update_plot_with_active_season` 兼容地块编辑复用 `_update_season_row`。兼容入口的地块字段与当前茬次变更同改同回滚，当前茬次在获得写锁后查询。
- `_validate_season_record_dates` 在该写事务内检查所有 `season_id` 关联台账，不过滤 `deleted_at`。新范围排除已有作业日期时返回 `409 / CONFLICT`，提示影响总条数及回收站条数；所有本次修改均不提交。开始/结束日包含首尾，null 表示该侧无边界，结束日早于开始日仍返回 422。
- 台账新增和编辑在各自写事务内经 `_resolve_record_season` 最终复核归属、已知日期范围、自动归茬及默认作物，不再采用服务层锁外选好的茬次和默认作物。省略、明确 null、明确 ID 三种原 API 语义保留；错误归属的初查仍在服务层保留既有 404 行为。
- 不回写历史台账的日期、归属、作物、删除标记或内容，不批量清理既有数据；合法的茬次修改也保持台账原始行不变。无 ORM、通用事务框架、新迁移或依赖。

主要修改：[repositories.py](../../../backend/app/repositories.py)、[services/farm.py](../../../backend/app/services/farm.py)。回归：[test_farm_transactions.py](../../../backend/tests/test_farm_transactions.py)。架构与覆盖说明同步到 `docs/ARCHITECTURE.md`、`docs/TESTING.md`。

故障测试使用临时 SQLite 的真实 `BEFORE INSERT` 触发器，分别使第一、第二次 INSERT 失败，验证无地块/第一茬残留、正常重试成功。另在第二次 INSERT 前用独立读连接确认看不到未提交的地块，并记录同一连接只有一次 BEGIN 和 COMMIT。兼容编辑还注入茬次 UPDATE 异常，验证地块字段一并回滚。

日期测试覆盖开始/结束/组合冲突、正常与回收站混合及仅回收站台账、准确影响条数、合法收窄和扩大、空边界、首尾日期、未归茬/其他茬次/其他用户不误阻止、直接数据层写入不能绕过校验、历史行逐字段保留，以及服务准备后改变日期或新增重叠茬次时的最终复核。

并发测试采用两个独立线程和数据库连接，用事件在第一写者持锁后暂停，并通过 SQLite trace 确认第二个连接已执行到 `BEGIN IMMEDIATE`，再释放第一写者，无 sleep 竞争猜测。覆盖台账新增/编辑与改期的两种提交顺序，以及兼容地块入口。改期先提交则越界台账写入返回 422；台账先提交则冲突改期返回 409。最终检查全部关联日期/归属、`foreign_key_check` 和 `integrity_check`。

现有测试调整：回收站测试原先要求正常接口允许制造日期冲突，已改为断言拒绝；其恢复入口防线继续用显式 SQL 模拟历史/外部损坏后验证。完整测试首轮有两项 CSV 夹具错误，原因是 2025 年台账被直接写入 2026 年才开始的其他地块茬次；仅修正这些测试茬次的开始日以覆盖原作业日期，保留导出筛选及隔离断言，没有放松应用校验或改写业务数据。
